# 화면 상태 빠짐 검사

“이 화면이 이런 상황에서는 어떻게 보이지?”가 **디자인에도, 코드에도** 있는지 찾는 매뉴얼이에요.

## 순서

1. **범위 받기** — 어떤 화면(또는 플로우)을 볼지 물어요. Figma 프레임 링크, 코드 화면 주소(`/prototype/...`) 중 있는 것을 받아요.
2. **Figma 보기** — `design-system/figma-log.md`에 기록이 있으면 그걸 써요. 없을 때만 Figma MCP로 읽고 바로 기록해요.
   - 플로우 전체는 `get_metadata`로 프레임 이름을 먼저 봐요. “빈”, “에러”, “로딩”, “disabled” 같은 이름의 프레임·배리언트가 있는지.
3. **코드 보기** — 그 화면의 `app/prototype/…/page.tsx`, 쓰는 컴포넌트(`components/ui/`, 화면 공통 틀), 데이터(`mocks/`)를 읽어요.
   - 예: 목록이 0개일 때 분기, `disabled`, `hover:`·`active:`·`focus-visible:` 클래스, `?data=empty|long|many` 같은 경계 데이터
4. **기준 8개로 표 만들기** — 화면에 나오는 요소마다, 기준별로 Figma / 코드 칸에 ✓ · ✗ · 해당 없음 · 확인 필요를 적어요.
5. **보고와 다음 제안** — 아래 보고 형식으로 보여 주고, 빠진 상태를 Figma에 먼저 그릴지, 코드 흉내부터 넣을지 사용자가 고르게 해요.

## 기준 (사용자가 고른 8개)

**화면 상태**
1. **빈 상태** — 목록·데이터가 0개일 때
2. **로딩** — 데이터를 불러오는 동안
3. **에러** — 실패했을 때 (제출 실패, 재생 실패, 링크 만료 등)
4. **긴 글·많은 목록** — 이름·문구가 아주 길거나 항목이 많을 때

**요소 상태** (버튼·선택지·입력칸)
5. **hover·pressed** — 마우스를 올렸을 때·눌렀을 때
6. **disabled** — 조건이 안 맞아 누를 수 없을 때
7. **포커스·입력 오류** — 키보드로 선택됐을 때, 입력이 잘못됐을 때
8. **선택됨·입력됨** — 고른 선택지, 글을 적은 입력칸

## 상태 표시 뜻

- ✓ 있음 · ✗ 없음
- **해당 없음** — 그 상황이 생길 수 없을 때만. 이유를 한 줄로 (예: “입력칸 없음”)
- **확인 필요** — 있어야 하는지 디자인 의도를 모를 때. 사용자에게 물어요.

## 보고 형식

맨 위에 한 줄: **빠진 상태 N개 (Figma N · 코드 N), 확인 필요 M개**

| # | 기준 | 요소 / 화면 | Figma | 코드 | 고칠 곳 |
|---|---|---|---|---|---|
| 1 | 빈 상태 | 장면 목록 | ✗ | 빈 바만 나옴 | Figma › 장면 0개 디자인 |
| 6 | disabled | 피드백 제출 버튼 | ✗ | ✗ (항상 눌림) | Figma › disabled 모습 → 코드 |

## 규칙

- **Figma를 고치지 않아요.** 보고만 해요. (`use_figma` 같은 수정 도구를 쓰지 않아요)
- **모르는 건 추측하지 않아요.** “이 화면에 로딩이 필요한가?”처럼 의도를 모르면 **확인 필요**로 적고 물어요.
- 검사하는 동안 코드를 고치지 않아요. 고치는 건 사용자가 고른 뒤에 `build-screen`·`build-component`로 해요.
- Figma에 없는 상태를 코드에 먼저 지어내지 않아요. 코드 흉내가 필요하면 사용자에게 먼저 물어요.

## 만든 이유

- 2026-11-12: Hilit 지인 피드백을 만들며 장면 0개·긴 장면 이름·장면 8개 화면, “피드백 제출” disabled 모습, 제출 후·실패 화면이 Figma에 없어서 코드에서 비워 두거나 되물어야 했어요. 화면을 설계할 때와 넘기기 전에 상태가 다 있는지 한 번에 보려고 만들었어요.
