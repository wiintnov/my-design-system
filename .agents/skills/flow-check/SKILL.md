# 유저플로우 테스트

## 순서

1. **체크리스트 만들기** — `prototype/screens.ts`의 플로우마다 `design-system/flow-test.md`에 표를 만들어요.

   | # | 하는 일 | 기대 결과 | 결과 | 메모 |
   |---|---|---|---|---|
   | 1 | /prototype › ‘상품 목록’ 열기 | 카드 12개가 보여요 | ☐ | |
   | 2 | 첫 카드 누르기 | 상품 상세로 넘어가요 | ☐ | |

   꼭 넣을 것: 모바일 폭(휴대폰으로 링크 열기), 뒤로가기, 긴 텍스트·빈 상태 데이터, 마지막 화면에서 처음으로.
2. **테스트 안내** — 사용자에게 배포 링크(없으면 localhost)와 표를 주고 직접 눌러 보게 해요. 휴대폰으로도 열어 보라고 해요.
3. **결과 기록** — 사용자가 말하는 결과를 표의 결과(✓/✗)와 메모에 적어요. 스크린샷을 주면 무엇이 문제인지 읽어서 적어요.
4. **정리** — 문제를 “Figma에서 고칠 것 / 코드에서 고칠 것 / 플로우를 다시 정할 것”으로 나눠 보여 주고, 무엇부터 고칠지 사용자가 고르게 해요.

## 규칙

- 테스트는 사용자가 직접 눌러 보는 게 기본이에요. AI가 대신 통과시키지 않아요.
- 고칠 곳의 판단(디자인 의도)은 사용자에게 물어요.
