# 스킬 규격 체크리스트

기준: Agent Skills 표준 (https://agentskills.io/specification), Anthropic skill-creator.
`npm run check:skills`가 ✓ 표시 항목을 자동으로 검사해요.

## 폴더 구조

```
.claude/skills/<이름>/
├── SKILL.md        # 필수: 머리말(name, description) + 순서
├── references/     # 선택: 길거나 가끔 필요한 설명 (필요할 때만 읽힘)
├── scripts/        # 선택: 매번 똑같이 돌아야 하는 검사·변환 코드
└── assets/         # 선택: 템플릿, 이미지, 표 같은 재료
```

- 본문에서 다른 파일을 가리킬 땐 스킬 폴더 기준 상대 경로로: `references/xxx.md`
- 가리키는 깊이는 한 단계만. references 안에서 또 다른 파일로 이어지지 않게.

## 머리말 (frontmatter)

- ✓ `name` 필수. 1~64자, **소문자·숫자·하이픈만**, 하이픈으로 시작·끝 X, `--` X
- ✓ `name` = 폴더 이름 (서브에이전트는 파일 이름)
- ✓ `description` 필수, 1024자 이하
- 선택: `license`, `compatibility`, `metadata`(예: author, version), `allowed-tools`(실험적)

## description 쓰는 법

AI는 **name과 description만 보고** 스킬을 꺼낼지 정해요. 본문은 꺼낸 뒤에야 읽어요.

1. **무엇을 하는지** — 동사로 시작: “Figma 프레임을 점검해 빠진 상태를 표로 알려 준다.”
2. **언제 쓰는지** — 상황: “개발자에게 넘기기 전에”
3. **사용자가 실제로 할 말** 2~4개: “넘겨도 돼?”, “빠진 거 있어?”
4. **조금 적극적으로** — AI는 스킬을 덜 꺼내는 경향이 있어요. “스킬 이름을 말하지 않아도 ~한 상황이면 반드시 이 스킬을 쓴다”처럼 써요.
5. 너무 넓게 쓰지 않기 — “디자인 도우미”, “버튼 관련” ✗

## 본문

- ✓ 500줄 이하 (권장: 한 화면, 100줄 안쪽)
- 구성: 순서(번호) → 기준·체크리스트 → 규칙(하면 안 되는 것) → 보고 형식
- 항상 지켜야 하는 규칙은 스킬이 아니라 `AGENTS.md`로
- 매번 기계적으로 같은 검사는 말로 쓰지 말고 `scripts/`에 코드로 (예: 키트의 `scripts/check-design.mjs`)

## 테스트

- 꺼내져야 하는 말 2개, 꺼내지면 안 되는 비슷한 말 1개로 시험
- 너무 단순한 부탁(“이 파일 읽어줘”)으로는 스킬이 안 꺼내질 수 있어요. 실제 일 단위로 시험해요.
