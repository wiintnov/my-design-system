# 스킬 틀

`<>` 부분을 채워서 `.claude/skills/<이름>/SKILL.md`로 저장해요.

```markdown
---
name: <영문-소문자-하이픈>
description: <무엇을 하는지 한 문장>. <언제 쓰는지>. "<사용자가 할 말 1>", "<말 2>", "<말 3>" 같은 요청에 쓴다. 스킬 이름을 말하지 않아도 <이런 상황>이면 반드시 이 스킬을 쓴다.
---

# <한글 제목>

## 순서
1. <먼저 확인할 것 — 예: figma-log.md에 기록이 있는지>
2. <입력 받기 — 예: Figma 프레임 링크>
3. <실제 작업>
4. <결과 보여주기 — 아래 보고 형식>

## 기준
- <사용자의 판단 기준을 사용자 말 그대로>

## 보고 형식
| <열1> | <열2> | <고칠 곳> |
|---|---|---|

## 규칙
- <절대 하면 안 되는 것>
```

## 채운 예: 핸드오프 전 점검

```markdown
---
name: handoff-check
description: 개발자에게 넘기기 전에 Figma 프레임을 점검해 빠진 상태·변수 미연결·그리드 밖 값을 표로 알려 준다. "핸드오프 전에 봐줘", "넘겨도 돼?", "빠진 거 있어?" 같은 요청에 쓴다. 스킬 이름을 말하지 않아도 사용자가 화면을 개발로 넘기려는 상황이면 반드시 이 스킬을 쓴다.
---

# 핸드오프 전 점검

## 순서
1. figma-log.md에 이 프레임 기록이 있는지 본다
2. 없으면 프레임 링크를 받아 Figma MCP로 한 번 읽고 기록한다
3. 아래 기준으로 본다
4. 결과를 표 하나로 보여준다

## 기준
- 모든 색이 Variables에 연결돼 있다
- 간격이 4px 그리드다
- Hover·Pressed·Disabled 상태가 있다
- 빈 화면·에러·로딩 상태가 있다

## 보고 형식
| 항목 | 상태 | 고칠 곳 |
|---|---|---|

## 규칙
- Figma를 고치지 않는다. 보고만 한다.
```
