# 서브에이전트 만들기 가이드

> 한 줄 요약: **결과만 보고받으면 되는 일은 서브에이전트에게 맡겨요.**

## 서브에이전트가 뭐예요?

팀장(코딩 에이전트)이 일을 맡기는 **직원**이에요. 따로 떨어진 방에서 일하고 결과만 보고해요.
`.claude/agents/<이름>.md` 파일 하나가 동료 한 명이에요.

스킬과 가장 큰 차이는 **대화가 섞이지 않는다**는 거예요.
서브에이전트가 파일 50개를 읽어도 내 대화에는 결과 요약만 돌아와요.
그래서 대화가 길어져도 AI가 헷갈리지 않아요.

## 스킬로 할까, 서브에이전트로 할까?

| 질문 | 예 → | 아니오 → |
|---|---|---|
| 중간 과정을 내가 같이 보며 고쳐야 하나요? | 스킬 | 다음 질문 |
| 많이 읽고 오래 걸리나요? (파일 여러 개, Figma 여러 프레임) | 서브에이전트 | 다음 질문 |
| 만든 사람과 **다른 눈**으로 봐야 하나요? (검수, 리뷰) | 서브에이전트 | 스킬 |

이 키트의 `figma-reviewer`가 대표 예예요. 컴포넌트를 만든 대화와 떨어져서, Figma와 코드를 새 눈으로 비교하고 차이 표만 돌려줘요.

## 만드는 법: AI에게 맡기기

```
이 검수 과정을 서브에이전트로 만들어줘. 파일은 고치지 말고 보고만 하게.
```

## 서브에이전트 파일 해부

```markdown
---
name: a11y-reviewer
description: 만든 컴포넌트나 화면의 접근성(색 대비, 터치 영역, 포커스)을 검사할 때 사용. 파일을 고치지 않고 문제 목록만 보고한다.
---

너는 접근성 검수 담당이야. 읽기 전용으로 일해. 파일을 만들거나 고치지 마.

## 순서
1. 대상 컴포넌트 파일과 app/globals.css를 읽는다
2. 글자색/배경색 대비를 계산한다 (본문 4.5:1, 큰 글자 3:1)
3. 버튼·링크의 터치 영역이 44px 이상인지 본다
4. 키보드 포커스 표시가 있는지 본다

## 보고 형식 (디자이너가 읽어)
- 맨 위 한 줄 결론: "통과 n, 문제 n"
- 표: 어디 / 무엇 / 기준 / 고칠 곳
- 확신이 없으면 "확인 필요"로. 추측을 사실처럼 쓰지 마.
```

| 부분 | 쓰는 요령 |
|---|---|
| `description` | 언제 맡길지 + **무엇을 하지 않는지**(“고치지 않는다”) |
| 첫 문장 | 역할과 권한. “읽기 전용” 같은 선을 분명히 |
| 순서 | 스킬과 같아요. 번호로 |
| 보고 형식 | **가장 중요.** 내가 받을 결과의 모양을 정해 두면 매번 같은 표로 와요 |
