# 스킬 만들기 가이드

> 한 줄 요약: **같은 부탁을 세 번 했다면, 스킬로 만들 때예요.**

## 스킬이 뭐예요?

코딩 에이전트(Claude Code·Codex)를 **팀장**, 서브에이전트를 **직원**이라고 하면, 스킬은 **업무 매뉴얼**이에요.
팀장과 직원이 필요할 때 꺼내 보는 “이 일은 이 순서로, 이 기준으로” 문서예요.
`.claude/skills/<이름>/SKILL.md` 파일 하나가 스킬 하나예요.

| | 규칙서 `AGENTS.md` | 스킬 | 서브에이전트 |
|---|---|---|---|
| 비유 | 사내 규정 | 업무 매뉴얼 | 직원 |
| 언제 읽나 | 매 대화 시작마다 항상 | 관련 부탁이 왔을 때만 | 일을 맡길 때만 |
| 어디서 일하나 | — | 지금 대화 안에서 | 따로 떨어진 방에서, 결과만 보고 |
| 넣을 것 | 언제나 지켜야 할 짧은 규칙 | 순서가 있는 반복 작업 | 오래 걸리는 검토·조사 |
| 예 | “색은 토큰만” | “버튼을 Figma 기준으로 만들기” | “Figma와 대조 검수” |

**헷갈리면 스킬로 시작하세요.** 대부분의 반복 작업은 스킬이면 충분해요.

## 가장 중요한 것: 매뉴얼은 ‘불편함’에서 시작해요

**왜 이 스킬이 필요한지 먼저 고민해야 해요.** 매뉴얼대로 일해 봤을 때 내가 느끼는
**감각적인 불편함**(“보기 불편해”, “매번 같은 말을 해”)이나
**근거가 있는 불편함**(“3px 오류가 3번 나왔어”, “디자이너에게 2번 되돌아갔어”)을 찾아낼 수 있어야 해요.

1. 매뉴얼대로 일을 한 번 끝까지 해 본다
2. 불편했던 점을 적는다 (감각적 / 근거적)
3. 그 불편함이 다시 안 생기도록 기준으로 바꿔 매뉴얼에 넣는다 → 다시 1로

### 사례: `playground-polish`는 왜 생겼을까

- **목적:** `/playground`는 디자이너가 코드 결과를 Figma와 나란히 대조하는 검수 화면이에요.
- **근거적 불편함:** 1차 프로젝트에서 3px 같은 어긋남이 개발이 끝난 뒤에야 발견됐어요. 대조할 화면이 없었어요.
- **감각적 불편함:** 개발자용 미리보기는 토큰 이름·실제 값이 안 보이고, 상태(눌렀을 때 등)는 마우스를 올려야만 보였어요.
- **그래서 매뉴얼에 넣은 기준:** 견본마다 토큰 이름 + 실제 값, 모든 상태를 한 표로, 상태 고정 보기, 밝은/어두운 배경, Figma 페이지 순서, 컴포넌트는 건드리지 않기.

## 스킬 후보 찾는 법

- 같은 문장을 AI에게 **세 번째** 붙여넣고 있다
- 매번 “아 그리고 이것도…”라고 **같은 조건을 덧붙인다**
- 동료에게 “이건 이렇게 해”라고 **설명한 적이 있다**
- 결과물을 볼 때마다 **같은 체크리스트**로 검사한다

떠오르면 바로 만들지 말고 [`skill-backlog.md`](skill-backlog.md)에 한 줄 적어 두세요. AI도 반복을 발견하면 여기에 적고, 작업이 끝날 때 가끔 “스킬로 만들어 둘까요?”라고 먼저 물어봐요.

### 뭘 만들지 모르겠다면: 처음 만들기 좋은 것

| 이름(예) | 종류 | 무엇을 |
|---|---|---|
| `handoff-check` | 스킬 | 넘기기 전 빠진 상태·변수 미연결·그리드 밖 값 점검 |
| `state-coverage` | 스킬 | 빈 화면·로딩·에러 상태가 다 있는지 확인 |
| `copy-tone` | 스킬 | 버튼·에러 문구를 우리 서비스 말투로 |
| `feedback-filter` | 스킬 | 받은 피드백을 사용자 문제 / 취향 / 정책으로 나눠 정리 |
| `a11y-reviewer` | 서브에이전트 | 대비·터치 영역·포커스 검사, 보고만 |

AI에게 `처음 만들기 좋은 스킬 추천해줘`라고 하면 내 상황에 맞게 골라 줘요.

## 만드는 법: AI에게 맡기기

```
방금 한 과정을 스킬로 만들어줘.
```

`new-skill` 스킬이 알아서 아래를 진행해요.
1. 비슷한 스킬이 이미 있는지 확인 (있으면 고치자고 제안)
2. 스킬 / 서브에이전트 / AGENTS.md 규칙 중 무엇이 맞는지 고르기
3. 세 가지 질문: **언제 쓰나요? 어떤 순서인가요? 절대 하면 안 되는 건?**
4. 파일 작성 → `AGENTS.md` 표에 등록 → 써 보기

## 스킬 파일 해부

```markdown
---
name: handoff-check
description: 개발자에게 넘기기 전에 Figma 프레임을 점검할 때 사용. "핸드오프 전에 봐줘", "넘겨도 돼?", "빠진 거 있어?" 같은 요청에 쓴다.
---

# 핸드오프 전 점검

## 순서
1. 프레임 링크를 받아 Figma MCP로 읽는다 (figma-log.md 먼저 확인)
2. 아래 체크리스트로 본다
3. 결과를 표 하나로 보여준다: 항목 / 상태 / 고칠 곳

## 체크리스트
- 모든 색이 Variables에 연결돼 있다
- 간격이 4px 그리드다
- Hover·Pressed·Disabled 상태가 있다
- 빈 상태·에러 상태 화면이 있다

## 규칙
- Figma를 고치지 않는다. 보고만 한다.
```

| 부분 | 역할 | 쓰는 요령 |
|---|---|---|
| `name` | 부르는 이름 (Claude Code `/handoff-check`, Codex `$handoff-check`) | 영문 소문자와 `-`만. 짧게 |
| `description` | **AI가 “지금 꺼낼 때인지” 판단하는 유일한 근거** | 언제 쓰는지 + 사용자가 실제로 할 말 2~3개 |
| 순서 | 매번 같은 결과가 나오게 | 번호로. 한 단계 = 한 동작 |
| 체크리스트 | 판단 기준 | 내 머릿속 기준을 글로 꺼내는 곳 |
| 규칙 | 하면 안 되는 것 | 사고가 났던 경험을 적어요 |

## 표준 규격 (업계 공통)

스킬은 Anthropic이 공개한 **Agent Skills 표준**([agentskills.io](https://agentskills.io/specification))을 따라요.
이 규격을 지키면 Claude Code와 Codex 등 이 표준을 지원하는 도구 어디서나 같은 스킬을 쓸 수 있어요.

```
.claude/skills/<이름>/
├── SKILL.md        # 필수: 머리말(name, description) + 순서
├── references/     # 선택: 길거나 가끔 필요한 설명
├── scripts/        # 선택: 매번 똑같이 돌아야 하는 검사 코드
└── assets/         # 선택: 템플릿, 이미지 같은 재료
```

| 규칙 | 내용 |
|---|---|
| `name` | 1~64자, 소문자·숫자·하이픈만, **폴더 이름과 같게** |
| `description` | 1024자 이하, **무엇 + 언제 + 사용자가 할 말** |
| 본문 길이 | 500줄 이하. 길어지면 `references/`로 나눠요 |
| 읽히는 순서 | ① name·description은 항상 → ② 본문은 꺼낼 때 → ③ references·scripts는 필요할 때만 |

`npm run check:skills`로 규격을 자동 검사할 수 있어요. 처음부터 외울 필요는 없어요. `new-skill` 스킬이 이 규격대로 만들어 줘요.

## description이 제일 중요해요

AI는 스킬을 **덜 꺼내는 경향**이 있어요. 그래서 description은 조금 적극적으로 써요.
“스킬 이름을 말하지 않아도 ~한 상황이면 반드시 이 스킬을 쓴다” 같은 문장을 끝에 붙이면 잘 꺼내져요.

| 나쁜 예 | 왜 | 좋은 예 |
|---|---|---|
| `디자인 도우미` | 언제 쓰는지 모름 | `개발자에게 넘기기 전 Figma 프레임을 점검할 때 사용` |
| `버튼 관련 작업` | 너무 넓어서 엉뚱할 때 꺼냄 | `Figma 버튼 컴포넌트를 코드로 만들 때 사용` |
| 사용자 말 예시 없음 | 내가 실제로 하는 말과 연결이 안 됨 | `"넘겨도 돼?", "빠진 거 있어?" 같은 요청에 쓴다` |

## 다 만들고 나서 체크

- [ ] `/<이름>`(Claude Code) 또는 `$<이름>`(Codex)으로 불렀을 때 순서대로 진행된다
- [ ] description에 적은 말을 했을 때 **부르지 않아도** 꺼내진다
- [ ] 상관없는 부탁에는 꺼내지지 **않는다**
- [ ] 본문이 한 화면 안에 들어온다 (길면 둘로 나누기)
- [ ] 비슷한 스킬이 두 개가 되지 않았다
- [ ] `AGENTS.md`의 표에 한 줄 추가했다

## 흔한 실수

- **비슷한 스킬을 여러 개 만든다** → 서로 다른 말을 해요. 기존 스킬을 고치세요.
- **스킬에 “항상” 규칙을 넣는다** → 스킬은 필요할 때만 읽혀요. 항상 지킬 건 `AGENTS.md`로.
- **한 스킬에 다 넣는다** → 길어지면 AI가 중간을 놓쳐요. 일 하나 = 스킬 하나.
- **만들고 안 고친다** → 결과가 이상하면 바로 “이 스킬에서 3번은 빼줘”처럼 말로 고치세요. 스킬은 키우는 거예요.
