# 나만의 템플릿으로 정리하기

가이드: `docs/3-my-template.md`. 시작 전에 읽어요.

## 0. 지금 단계 알려주기

README의 성장 경로(Lv.1~5) 기준으로 현재 단계를 판단해 알려 줘요.
- `design-system/PROGRESS.md` 1~10 완료 여부 → Lv.1
- `AGENTS.md`에 키트 기본 외 규칙이 있는지 → Lv.2
- 키트 기본 10개 외 스킬이 있는지 → Lv.3
- `figma-reviewer` 외 서브에이전트가 있는지 → Lv.4
Lv.3 미만이면 “템플릿으로 만들기 전에 스킬 하나는 만들어 보길 권해요”라고 제안하되, 사용자가 원하면 진행해요.

## 1. 남길 것 / 뺄 것 나누기

레포 전체를 훑고 표로 보여 줘요. **사용자가 고를 때까지 아무것도 지우지 않아요.**

| 항목 | 위치 | 제안 | 이유 |
|---|---|---|---|
| 버튼 컴포넌트 | components/ui/Button.tsx | 남김 | 다음 프로젝트에도 기본 |
| 이번 프로젝트 화면 | app/checkout/ | 뺌 | 이 프로젝트 전용 |
| Figma 기록 | design-system/figma-log.md | 비움 | 파일마다 다름 |
| 진행 체크 | design-system/PROGRESS.md | 초기화 | 새로 시작할 사람용 |

## 2. 정리하기 (확인받은 것만)

- 뺄 것은 삭제 전에 목록을 한 번 더 보여 주고 확인받아요.
- `figma-log.md`는 형식 예시만 남기고 비워요. `PROGRESS.md`는 체크를 모두 해제해요.
- `docs/skill-backlog.md`는 남길지 비울지 물어요.

## 3. 문서 다시 쓰기

- `README.md` 맨 위를 사용자 템플릿 소개로 바꿔요: 이름, 누구를 위한 건지, 이 템플릿만의 규칙·스킬 목록.
- 원본 출처 한 줄을 남겨요: “AI Native Designer Kit에서 시작함”.
- `CHANGELOG.md`를 만들어 키트 원본 대비 바뀐 것을 적어요: 추가한 규칙, 만든 스킬·서브에이전트, 바꾼 토큰.

## 4. 확인하고 저장

- `npm run check`, `npm run build` 통과 확인.
- `ship` 스킬로 브랜치 → 커밋 → PR → 머지.

## 5. 템플릿으로 지정 (사용자가 브라우저에서)

1. GitHub 내 레포 › **Settings**
2. General 맨 위 **Template repository** 체크
3. 레포 첫 화면에 **Use this template** 버튼이 생겼는지 확인
4. 동료에게 레포 주소와 “Use this template으로 시작해서 Claude Code나 Codex에게 ‘시작하자’” 안내 문구를 전달

## 규칙

- 지우기·초기화는 항목마다 확인받아요. 되돌리기 쉽도록 꼭 브랜치에서 해요.
- 사용자가 만든 스킬·규칙은 절대 임의로 빼지 않아요.
